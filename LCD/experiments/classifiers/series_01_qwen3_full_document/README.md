# Qwen3-8B full-document classifier

This experiment trains a three-class Qwen3-8B classifier on the 30 reviewed `Full` court decisions. Every labeled hypothesis–premise pair receives the complete source DOCX text. The prompt presents `Контекст:` before the cited lawbook premise and hypothesis. Only the expert label supplies the response; `model_prediction` is ignored.

The isolated copy records both filenames, Excel row, article citation, pair text, expert label, and document context. A manifest hashes each source and the CSV. If a complete example exceeds 8,192 tokens, preparation keeps the end of the court decision and shortens only its context field. The cited premise, hypothesis, instructions, and response remain intact.

Training uses response-only loss, Qwen3-8B 4-bit NF4 QLoRA, microbatch one, gradient checkpointing, paged 8-bit AdamW, and PyTorch SDPA. The loss computes vocabulary logits only for the response tokens and their immediately preceding position, while the transformer still processes the full document. The separate probe repeats source document text to construct an exact 8,192-token example, performs one forward, backward, and optimizer update, records memory and timing, and saves no adapter. The probe text never enters training. Qwen3-8B has a native 32,768-token context window, so this experiment needs no YaRN setting. See the [PEFT quantization guide](https://huggingface.co/docs/peft/developer_guides/quantization), [PyTorch SDPA documentation](https://docs.pytorch.org/docs/main/generated/torch.nn.functional.scaled_dot_product_attention.html), and [Qwen3-8B model card](https://huggingface.co/Qwen/Qwen3-8B).

`Full` is the sole training source here. There is no validation set or quality evaluation in this iteration; training on `Full` rules out reporting a held-out `Full` test score. Built-in SDPA is the starting attention implementation; a separate FlashAttention install is outside this recipe because its [Windows installation support is less established](https://github.com/Dao-AILab/flash-attention/blob/main/README.md).

The first disposable GPU probe used full-sequence logits and reached 31.2 GB peak reserved memory, above the device's 25.8 GB reported capacity. The selective-logit probe completed the same 8,192-token update with 17.9 GB peak allocated and 18.7 GB peak reserved memory in a 13.3-second step. It **passed the memory gate**. These figures are decimal GB. The two reports are under ignored `local/experiments/classifiers/series_01_qwen3_full_document/probe/` and `probe_selective/`. No adapter training or quality evaluation has run yet.

A disposable loss comparison used the first reviewed pair with its document context omitted: 1,113 tokens, including five supervised response tokens. It ran full-sequence logits with prompt labels masked, then selective response logits on the same loaded QLoRA model and restored random state. The losses were 5.3974819183 and 5.3974928856 (absolute difference 0.0000109673). The full-logit masked response calculation exactly matched the built-in full loss. Across 504 LoRA gradient tensors, the overall relative L2 difference was 0.89% and the largest per-tensor relative L2 difference was 1.34%; all were within the 2% BF16 norm tolerance. A stricter elementwise check at `atol=1e-4, rtol=1e-3` passed 260 tensors. A full-logit versus full-logit control produced exactly equal losses and gradients. The relative response-logit difference was 0.000116%, consistent with small numerical differences from the changed output projection shape. The comparison supports equivalent single-step training behavior within BF16 tolerance; it is not a held-out quality evaluation. Reports are under ignored `local/experiments/classifiers/series_01_qwen3_full_document/loss_comparison/` and `loss_comparison_full_repeat/`.

Commands and configurable arguments are in the [classifier instructions](../instructions.md). Private source data, exports, adapters, and metrics stay under ignored `local/` paths.
