# Classifiers: 8k LoRA training context

This experiment asks whether the four existing classifier model families—Llama-3.1-8B, Ministral-8B-Instruct-2410, Qwen3-8B, and T-lite-it-2.1—can complete a LoRA training update with an **8,192-token prompt-plus-label example** on the available 24 GB GPU. The current shared QLoRA trainer uses a 2,560-token limit, a microbatch of one, 4-bit base weights, and gradient checkpointing. The 8k result must be measured, not inferred from the model's advertised context window or an inference-only run.

The first stage is a throwaway feasibility probe. The current `Full` benchmark provides links to original full decisions, making it possible to add document context to a pair prompt and reach a representative length. Use document text for the probe, but not Full labels. A probe succeeds for a model only when a genuine 8,192-token example completes forward computation, backward computation, and an optimizer update within 24 GB. Record the model and revision, token count, prompt composition, peak GPU memory, step time, attention implementation, quantization, checkpointing, and optimizer settings. Discard updated weights and optimizer state after the probe; it produces no benchmark score or reusable adapter.

Start with the current 4-bit LoRA recipe and profile memory. Investigate supported memory-efficient attention and activation-memory settings only as needed; document each attempted configuration and failure. [Transformers documents gradient checkpointing](https://huggingface.co/docs/transformers/grad_checkpointing), and [PyTorch documents scaled dot-product attention backends](https://docs.pytorch.org/docs/main/generated/torch.nn.functional.scaled_dot_product_attention.html). Feasibility is evaluated separately for each model; no success is assumed in advance.

After the 8k feasibility gate, the eventual training scripts must read only the rebuilt `train` and `dev` datasets from [data creation](../data_creation/README.md), with the rebuilt `test` split held out. The current `Full` benchmark is used only for the disposable memory probe. [Classifier instructions](instructions.md) describe the sequence and required records. This documentation pass adds no 8k runner or trained adapter.
