# Data creation

This experiment will rebuild the three-class classification datasets from scratch. Human experts choose the legal articles, assess the collected documents, supply rules for making contradictory operative sentences, and set the release criteria. Subagents collect and prepare evidence, apply the expert-approved modification rules, and propose pair labels. The corpus contains **original Russian court rulings**. Appeal decisions form a separate evidence pool for experts to study possible errors in original rulings; an appeal need not be matched to every corpus document. An appeal does not by itself prove that the original ruling contradicts a lawbook provision.

The original rulings are split by document or case into independent `train`, `dev`, and `test` sets **after** expert document review and **before** sentence processing. Sentences come from the final `ПОСТАНОВИЛ` section, using `razdel` and the current irrelevant-text filter, with any changes documented and reviewed. For all three splits, subagents may create synthetic contradictory hypotheses only under the expert-supplied rules. Aim for modified sentences to comprise one third of training hypotheses where feasible; if too few valid modifications exist, reduce the unmodified training hypotheses instead of admitting invalid contradictions.

For every hypothesis, run semantic lawbook retrieval and also check whether an explicit citation can be resolved exactly. If both routes return the same provision, retain one premise with both routes recorded. This dataset policy differs from the current inference pipeline, which uses exact citations before semantic fallback. Experts or subagents then assign each hypothesis–premise pair one label: `not mentioned`, `entailment`, or `contradiction`. The class targets apply to **pairs**, not documents or hypotheses: `train` 1:1:1; `dev` approximately 60:20:20 in the order just given. The `test` distribution is reported as observed, without sampling it to a target; approximately 70:25:5 would be welcome but is not a release condition.

Experts review every `dev` and `test` pair. They review a stratified sample of `train` pairs across articles, labels, and modification rules, plus every flagged or uncertain pair. Released records preserve the source document and URL, document type, split, original and modified hypothesis, applied rule, premise and citation, retrieval routes, proposed label, expert label when reviewed, and review status. Keep source documents, workbooks, and generated datasets under ignored `local/` paths. New native splits must not overwrite the historical `val.csv` or `Full` benchmark.

The collection checklist and staged procedure are in the [data-creation instructions](instructions.md). No collection runner or dataset has been created by this documentation pass.
